# 원스텝 인력관리 앱 요구사항 정의서 (초안 v0.1)

> 상태: 협의 중 · 최종 수정: 2026-10-26
> 미확정 항목은 `[확인 필요]`로 표시한다.

## 1. 배경

원스텝은 면접·필기시험·행사 대행 운영업체와 계약하고, 필요한 인원만큼 진행요원을 파견한다.

- 운영 인력은 모두 프리랜서다. 정직원은 없다.
- 인력 풀: 경력 5년 이상 핵심 인력 40~50명, 전체 약 550명
- 인력 풀은 10년간 지인의 비공개 링크, 그 지인의 지인으로 이어지는 추천 방식으로 넓어졌다.
- 관리자는 대표 1인이다.

### 현재 업무 흐름 (As-Is)

| 단계 | 현재 방식 |
|---|---|
| 모집 | 카카오톡 오픈톡방에 일정 공지 → 신청 |
| 선발 | 대표가 신청자 중에서 선발 |
| 계약 | 위드싸인으로 1인 건별 계약. 인력이 계약서에 주민번호·계좌번호·주소를 직접 기입 |
| 인원 정보 | 엑셀 |
| 확정 안내 | 확정 인원 톡방을 따로 개설해 인원수·이름 확인 |
| 현장 소통 | 오픈톡방 |
| 문제 인력 | 오픈톡방에서 내보내거나, 기억해 두었다가 다시 부르지 않음 |
| 정산 | 기타소득 8.8% 원천징수 후 지급 `[대표 확인 필요]`, 지급일은 15일 또는 말일 |

### 핵심 문제

1. **검증되지 않은 인력의 투입**: 오픈톡방은 누구나 들어올 수 있어 불특정 인원이 신청하고 투입될 수 있다. 시험·면접 현장은 신뢰가 중요해 회사 이미지에 직접 타격이 된다.
2. **정보 분산**: 모집(카톡), 계약(위드싸인), 인원 정보(엑셀), 정산이 흩어져 대표 혼자 관리하기 어렵다.
3. **인력 이력의 부재**: 노쇼·태도 문제가 기록되지 않고 대표의 기억에 의존한다.

## 2. 목표

- 검증된 회원만 일정을 보고 신청할 수 있게 한다.
- 모집 → 선발 → 계약 → 정산을 하나의 앱에서 처리한다.
- 인력별 참여 이력과 특이사항을 기록해 선발 근거로 쓴다.

### 하지 않는 것 (당분간)

- 현장 실시간 소통: 오픈톡방을 계속 사용한다. 앱은 행사별 톡방 링크만 안내한다.
- 보안서약서: 원스텝과 계약한 고객사가 현장에서 직접 받는다.

## 3. 사용자

| 사용자 | 설명 | 주 사용 환경 |
|---|---|---|
| 관리자 (대표) | 일정 등록, 선발, 계약, 정산, 인력 관리 | PC 웹 + 모바일 |
| 운영 인력 (프리랜서) | 일정 확인, 신청, 계약 서명, 정산 내역 확인 | 모바일 |

## 4. 주요 요구사항

### 4.1 회원 가입과 검증
- 가입은 **초대 링크**로만 가능하다. 링크에는 추천인이 기록된다. (기존 지인 추천 흐름을 그대로 옮긴다)
- 가입 후 대표가 **승인**해야 일정을 볼 수 있다.
- 회원 등급:
  - **핵심**: 경력 인력. 일정을 먼저 본다.
  - **일반**: 승인된 회원
  - **대기**: 가입했지만 승인 전
  - **제한**: 일정 열람과 신청 불가 (블랙리스트)
- 대표만 볼 수 있는 인력 메모와 이력(노쇼, 지각, 특이사항)을 기록한다.

### 4.2 일정(모집 공고)
- 유형: 필기시험, 면접, 행사
- 항목: 날짜, 시간, 장소, 필요 인원, 단가, 집합 안내, 고객사(내부용)
- **등급별 순차 공개**: 핵심 인력에게 먼저 공개하고, 대표가 정한 시점에 일반 회원에게 공개한다.
- 인원과 건수는 일정마다 다르므로 고정값을 두지 않는다.

### 4.3 신청과 선발
- 인력은 앱에서 신청하고, 신청을 취소할 수 있다.
- 대표가 신청자의 이력(참여 횟수, 메모)을 보며 **확정 / 대기 / 미선발**을 정한다. 선착순 아님.
- 확정자에게 알림을 보내고, 행사별 확정 톡방 링크를 확정자에게만 보여 준다.

### 4.4 전자계약
- 확정되면 행사 정보가 채워진 **건별 계약서**를 자동으로 만든다.
- 인력은 앱 안에서 서명한다. 주민번호·계좌·주소는 회원 정보에서 불러오고, 최초 1회만 입력한다.
- 서명된 계약서는 PDF로 보관하고, 서명 시각·서명자·문서 해시를 감사 기록으로 남긴다.
- 기본계약(연 1회) 방식 도입 여부는 `[추후 협의]`.

### 4.5 정산
- 행사별 지급액 = 단가 − 원천징수세액. **세율은 설정값**으로 둔다. (기타소득 8.8% / 사업소득 3.3% `[대표·세무사 확인 필요]`)
- 지급일(15일, 말일) 기준으로 지급 대상을 묶는다.
- 인력은 자기 정산 내역과 지급 상태를 앱에서 본다.
- 1차: 은행 대량이체용 엑셀 다운로드 + 지급 완료 처리
- 2차: 지급대행 API로 앱에서 바로 이체 (별도 사업자 계약 필요)

## 5. 비기능 요구사항

- **개인정보**: 주민번호는 원천징수(소득세법)를 근거로 수집하며, 법령상 **암호화 저장이 의무**다. 열람은 대표만, 열람 기록을 남긴다.
- **형태**: 웹 + 모바일 모두 지원. 하나의 반응형 웹앱(PWA)으로 시작하고, 홈 화면 설치를 지원한다.
- **유지보수**: 당분간 개발팀 2인이 운영하므로, 서버 관리가 적은 구조를 택한다.

## 7. 기술 스택 (안)

| 영역 | 선택 | 이유 |
|---|---|---|
| 프론트엔드 | Next.js (TypeScript), 반응형 + PWA | 웹과 모바일을 한 코드로 |
| 백엔드/DB | Supabase (PostgreSQL, 인증, 파일 저장소, 행 단위 권한) | 서버 운영 부담이 적음 |

| 알림 | 1차 웹 푸시/SMS, 2차 카카오 알림톡 | 알림톡은 비즈니스 채널 개설 필요 |

## 8. 미결 사항

1. 현장 역할 구분(총괄, 감독관, 안내 등)과 역할별 단가 차이
2. 원천징수 세목: 기타소득 8.8%인지 사업소득 3.3%인지 (반복·계속 수행이면 사업소득으로 보는 경우가 많아 세무사 확인 권장)
3. 신규 인력 검증 절차(신분증, 경력 확인, 사전 교육)와 평가 체계
4. 고객사의 앱 사용 여부
5. 목표 오픈 시점, 월 운영비 예산
6. 오픈톡방에 있는 기존 550명을 앱으로 옮기는 방법
