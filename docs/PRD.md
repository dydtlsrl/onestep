## 1. 개요

### 1.1 배경
원스텝은 면접·필기시험·행사 대행 운영업체와 계약하고, 필요한 인원만큼 진행요원을 파견한다.

- 운영 인력은 모두 프리랜서다. 정직원은 없다.
- 인력 풀: 경력 5년 이상 핵심 인력 40~50명, 전체 약 550명
- 인력 풀은 10년간 지인 추천(비공개 링크)으로 넓어졌다.
- 관리자는 대표 1인이다.

### 1.2 현재 방식과 문제

| 단계 | 현재 방식 | 문제 |
|---|---|---|
| 모집 | 오픈톡방에 일정 공지, 신청 받음 | 검증되지 않은 사람도 신청 가능 |
| 선발 | 대표가 선발 | 신청자의 과거 이력을 대표가 기억에 의존해 판단 |
| 계약 | 위드싸인 1인 건별 계약, 인력이 주민번호·계좌·주소를 매번 직접 기입 | 매번 같은 정보를 입력, 계약 비용 발생 |
| 인원 정보 | 엑셀 | 모집·계약·정산 정보와 연결되지 않음 |
| 확정 안내 | 확정 인원 톡방 개설 | (유지) |
| 문제 인력 | 오픈톡방에서 내보내거나 다시 부르지 않음 | 기록이 남지 않음 |
| 정산 | 원천징수 후 15일 또는 말일 지급 | 수작업 계산 |

**가장 큰 위험**: 시험·면접 현장은 신뢰가 중요하다. 검증되지 않은 인력 한 명이 회사 이미지에 직접 타격을 줄 수 있다.

### 1.3 목표
1. 초대받고 대표가 승인한 회원만 일정을 보고 신청한다.
2. 모집 → 선발 → 계약 → 정산을 하나의 앱에서 처리한다.
3. 인력별 참여 이력과 특이사항을 기록해 선발 근거로 쓴다.

### 1.4 하지 않는 것
- **현장 실시간 소통**: 오픈톡방을 계속 쓴다. 앱은 확정자에게만 톡방 링크를 보여 준다.
- **보안서약서**: 고객사가 현장에서 직접 받는다.
- **고객사용 화면**: 2차 이후 검토

### 1.5 MVP의 목적
**사용성 검증**. 대표와 핵심 인력 일부가 실제 일정 몇 건을 앱으로 처리해 보고, 기존 방식보다 편한지 확인한다. 성공 기준은 [9장](#9-성공-지표-사용성-검증) 참고.

## 3. 핵심 흐름

### 3.1 가입 흐름
```mermaid
flowchart LR
    A["대표가 초대 링크 생성"] --> B["오픈톡방 등에 링크 공유"]
    B --> C["인력이 링크 접속"]
    C --> D["카카오 또는 구글 로그인"]
    D --> E["가입 신청서 작성"]
    E --> F["승인 대기"]
    F -->|대표 승인| G["활동 회원 (등급 지정)"]

```

### 3.2 일정 흐름
```mermaid
flowchart LR
    A["일정 등록"] --> B["핵심 인력 공개"]

    D --> E["대표 선발 (확정·대기·미선발)"]

    F --> G["계약서 서명"]
    G --> H["행사 진행"]
    H --> I["출석 확인 (참석·지각·노쇼)"]
    I --> J["정산·지급"]
```

## 4. 기능 요구사항

우선순위: **P0** = MVP 필수, **P1** = MVP에 넣으면 좋음, **P2** = 2차

### 4.1 인증·가입 (AUTH)

| ID | 기능 | 우선순위 | 수용 기준 |
|---|---|---|---|
| AUTH-01 | 초대 링크 | P0 | 대표가 링크를 만들 수 있다 (메모, 만료일, 최대 사용 횟수). 링크 없이 접속하면 "초대 링크로만 가입할 수 있습니다"를 보여 준다. 만료되었거나 비활성화된 링크는 가입이 안 된다. |
| AUTH-02 | 소셜 로그인 | P0 | 카카오 로그인, 구글 로그인을 지원한다. 별도 비밀번호는 없다. |
| AUTH-03 | 카카오톡 인앱 브라우저 대응 | P0 | 내장 브라우저에서 구글 로그인이 차단되면 외부 브라우저에서 여는 방법과 버튼을 안내한다. 카카오·구글 로그인을 대상 기기에서 각각 검증한다. |
| AUTH-04 | 가입 신청서 | P0 | 이름, 휴대폰 번호, 활동 가능 지역, 경력 연수, 경력 사항, 추천인 이름(선택), 개인정보 수집·이용 동의(필수)를 입력한다. |
| AUTH-05 | 중복 가입 방지 | P0 | 같은 휴대폰 번호로는 한 번만 가입할 수 있다. (카카오와 구글로 따로 가입하는 것을 막음) |
| AUTH-06 | 승인 대기 화면 | P0 | 승인 전에는 "대표 승인 후 이용할 수 있습니다"만 보이고 일정은 보이지 않는다. |
| AUTH-07 | 가입 승인 | P0 | 대표가 신청서를 보고 승인(등급 지정) 또는 거절한다. 결과를 회원에게 알린다. |
| AUTH-08 | 회원별 추천 링크 | P2 | 설정에 따라 핵심 회원도 초대 링크를 만들 수 있다. 추천인이 자동 기록된다. |

### 4.2 회원 관리 (MEM)

| ID | 기능 | 우선순위 | 수용 기준 |
|---|---|---|---|
| MEM-01 | 회원 목록 | P0 | 이름·전화번호 검색, 등급·상태·지역 필터 |
| MEM-02 | 회원 상세 | P0 | 프로필, 참여 횟수, 노쇼·지각 횟수, 최근 참여일, 관리자 기록 타임라인 |
| MEM-03 | 등급 변경 | P0 | 핵심 ↔ 일반 변경 |
| MEM-04 | 활동 제한 | P0 | 사유를 적고 제한한다. 제한된 회원은 로그인해도 일정을 볼 수 없다. 제한 해제 가능. |
| MEM-05 | 관리자 기록 | P0 | 종류(메모·노쇼·지각·주의·칭찬)와 내용을 남긴다. 관련 일정을 연결할 수 있다. **회원에게는 보이지 않는다.** |
| MEM-06 | 내 정보 | P0 | 회원이 프로필과 정산 정보(주민번호, 은행, 계좌번호, 예금주, 주소)를 입력·수정한다. 주민번호와 계좌번호는 저장 후 가려서(마스킹) 보여 준다. |
| MEM-07 | 엑셀 가져오기 | P1 | 기존 엑셀 명단을 참고 자료로 불러온다. (계정은 각자 가입해야 하므로 승인 시 대조용) |
| MEM-08 | 평가 점수 체계, 현장 팀장 평가 | P2 | 추후 협의 |

### 4.3 단가표 (RATE)
역할 체계가 아직 자리 잡는 중이므로, 역할과 단가를 대표가 자유롭게 추가·수정할 수 있게 한다.

| ID | 기능 | 우선순위 | 수용 기준 |
|---|---|---|---|
| RATE-01 | 단가표 관리 | P0 | 역할 이름, 설명, 기본 단가를 등록·수정·숨김 처리한다. 순서를 바꿀 수 있다. |
| RATE-02 | 일정별 단가 | P0 | 일정을 등록할 때 단가표의 기본 단가를 불러오고, 그 일정에서만 금액을 바꿀 수 있다. 단가표를 나중에 바꿔도 이미 등록된 일정의 금액은 바뀌지 않는다. |

### 4.4 일정 (EVT)

| ID | 기능 | 우선순위 | 수용 기준 |
|---|---|---|---|
| EVT-01 | 일정 등록 | P0 | 유형(필기시험·면접·행사·기타), 제목, 고객사(내부용, 회원에게 비공개), 날짜, 집합 시간, 근무 시간, 장소·주소, 역할별 모집 인원과 단가, 안내사항, 확정자 톡방 링크, 신청 마감 일시, 지급 예정일 |
| EVT-02 | 순차 공개 | P0 | 핵심 인력에게 먼저 공개하고, 설정에 따라 일반 회원에게 공개한다. ([설정 SET-04](#49-설정-set)) |
| EVT-03 | 일정 상태 | P0 | 임시저장 → 핵심 공개 → 전체 공개 → 모집 마감 → 완료, 또는 취소 |
| EVT-04 | 회원용 일정 목록 | P0 | 내가 볼 수 있는 일정만 보인다. 남은 자리, 내 신청 상태를 표시한다. |
| EVT-05 | 일정 복사 | P1 | 같은 고객사의 반복 일정을 복사해서 날짜만 바꿔 등록한다. |
| EVT-06 | 일정 취소 | P0 | 대표가 취소하면 신청자 전원에게 알린다. 서명 전 계약 요청은 무효 처리된다. |

### 4.5 신청·선발 (APL)

| ID | 기능 | 우선순위 | 수용 기준 |
|---|---|---|---|
| APL-01 | 신청 | P0 | 모집 역할이 여러 개면 역할을 골라 신청한다. 한 일정에 한 번만 신청할 수 있다. |
| APL-02 | 신청 취소 | P0 | 선발 전에는 회원이 직접 취소한다. 확정 후 취소는 [설정 SET-06](#49-설정-set)을 따른다. |
| APL-03 | 선발 화면 | P0 | 신청자마다 등급, 참여 횟수, 노쇼·지각 횟수, 최근 관리자 기록을 함께 보여 준다. 확정·대기·미선발을 한 명씩 또는 여러 명을 한 번에 처리한다. 역할별 확정 인원/모집 인원을 표시한다. |
| APL-04 | 확정 안내 | P0 | 확정자에게 알림을 보내고, 확정자에게만 톡방 링크와 집합 안내를 보여 준다. 미선발자에게도 결과를 알린다. |
| APL-05 | 직접 추가 | P0 | 대표가 신청하지 않은 회원(전화로 섭외한 경우 등)을 확정자로 추가할 수 있다. |
| APL-06 | 출석 확인 | P0 | 행사 후 대표가 확정자별로 참석·지각·노쇼를 표시한다. 노쇼·지각은 회원 이력에 자동 반영된다. |
| APL-07 | 대기자 승격 | P1 | 확정자가 빠지면 대기자를 확정으로 바꾸고 알린다. |

### 4.6 전자계약 (CON)

| ID | 기능 | 우선순위 | 수용 기준 |
|---|---|---|---|
| CON-01 | 계약서 양식 관리 | P0 | 대표가 계약서 문구를 등록한다. `{{이름}}`, `{{행사명}}`, `{{일자}}`, `{{장소}}`, `{{역할}}`, `{{금액}}` 같은 자리표시자를 쓴다. 양식을 고치면 새 버전으로 저장되고, 이미 보낸 계약서는 바뀌지 않는다. |
| CON-02 | 서명 요청 | P0 | 확정자에게 계약서를 자동 생성해 서명을 요청한다. 일정 단위로 한 번에 보낼 수 있다. |
| CON-03 | 회원 서명 | P0 | 회원이 계약 내용을 확인한다 → 정산 정보가 비어 있으면 그 자리에서 입력한다(최초 1회) → 손글씨 서명 → 완료 |
| CON-04 | 서명 증빙 | P0 | 서명 완료 시 PDF를 만들어 보관한다. 서명 시각, IP, 기기 정보, 문서 해시값을 기록한다. 회원도 자기 계약서를 내려받을 수 있다. |
| CON-05 | 서명 현황 | P0 | 일정별로 서명 완료/미완료를 보여 주고, 미완료자에게 다시 알림을 보낸다. |
| CON-06 | 계약 무효 처리 | P0 | 확정 취소 시 계약을 무효 처리하고 사유를 남긴다. |
| CON-07 | 기본계약 방식 | P2 | [설정 SET-05](#49-설정-set)에서 "기본계약 + 건별 확인"을 고르면, 연 1회 기본계약 후 행사마다 간단한 확인 서명만 받는다. |

> 계약서 문구는 기존 위드싸인 계약서를 대표에게 받아 그대로 옮긴다. 문구의 법률 검토는 대표 측에서 한다.

### 4.7 정산 (PAY)

| ID | 기능 | 우선순위 | 수용 기준 |
|---|---|---|---|
| PAY-01 | 지급 항목 생성 | P0 | 출석 확인을 마치면 참석·지각자마다 지급 항목이 생긴다. 노쇼는 생기지 않는다. |
| PAY-02 | 금액 조정 | P0 | 연장 근무, 교통비 등 추가·차감 금액과 사유를 입력한다. |
| PAY-03 | 세금 계산 | P0 | 대표·세무사가 세목과 계산 규칙을 확정한 뒤 [설정 SET-01, SET-02](#49-설정-set)에 따라 소득세와 지방소득세를 계산한다. 확정 전에는 실제 지급액 확정·이체 엑셀 생성을 막는다. 적용 세목·세율·계산 규칙의 버전을 지급 항목에 저장해 이후 설정 변경이 과거 내역을 바꾸지 않게 한다. |
| PAY-04 | 지급일별 목록 | P0 | 지급일(15일·말일 등)별로 지급 대상과 합계를 본다. |
| PAY-05 | 이체용 엑셀 | P0 | 지급일별로 은행 대량이체용 엑셀(이름, 은행, 계좌번호, 금액)을 내려받는다. 내려받은 기록을 남긴다. |
| PAY-06 | 지급 완료 처리 | P0 | 지급 완료로 바꾸면 회원에게 알린다. 보류 처리도 가능하다. |
| PAY-07 | 내 정산 내역 | P0 | 회원이 지급 예정·완료 내역과 공제 세액을 본다. |
| PAY-08 | 앱에서 바로 이체 | P2 | 지급대행 서비스 연동. 별도 사업자 계약이 필요하다. |
| PAY-09 | 원천징수 신고 자료 | P2 | 지급명세서 작성용 자료를 내려받는다. |

### 4.8 알림 (NOTI)

| ID | 기능 | 우선순위 | 수용 기준 |
|---|---|---|---|

### 4.9 설정 (SET)
대표 확인이 필요한 설정이다. 금전·세무 규칙은 세무사 확인과 대표 승인 후 활성화한다. 2차 기능은 구현 시점에 설정 화면에 추가한다.

| ID | 항목 | 선택지 | 기본값 |
|---|---|---|---|
| SET-01 | 원천징수 세목 | ① 기타소득 8.8% ② 사업소득 3.3% ③ 원천징수 안 함 ④ 직접 입력 | 미확정. 실제 정산 전 대표·세무사 확인 필수 |
| SET-02 | 기타소득 과세최저한 | 적용 / 미적용 | 적용 |
| SET-03 | 지급일 규칙 | ① 월 2회 (15일·말일) ② 월 1회 (말일) ③ 일정마다 직접 지정 | ① 월 2회 |
| SET-03a | 지급일 유예 기간 | 행사일로부터 최소 N일 뒤의 가장 가까운 지급일 | 7일 (임시값, 대표 확인 필요) |
| SET-04 | 일반 회원 공개 방식 | ① 대표가 직접 공개 ② 핵심 공개 후 N시간 뒤 자동 공개 | ① 직접 공개 |
| SET-05 | 계약 방식 | ① 건별 계약 ② 기본계약 + 건별 확인 (2차) | ① 건별 계약 |
| SET-06 | 확정 후 회원 취소 | ① 대표에게 취소 요청만 가능 ② 행사 N일 전까지 직접 취소 가능 | ① 요청만 |
| SET-07 | 초대 링크 발급 권한 | ① 대표만 ② 핵심 회원도 가능 (2차) | ① 대표만 |
| SET-08 | 가입 시 성별 수집 | 수집 / 수집 안 함 | 수집 안 함 |

**세목 참고 (대표·세무사 확인용)**
- **기타소득 8.8%**: 일시적·우발적인 인적용역 대가에 쓴다. 필요경비 60%를 빼고 남은 40%에 소득세 20%와 지방소득세 2%를 매긴 결과다.
  과세최저한 때문에 1건 지급액이 125,000원 이하면 원천징수하지 않는다.
- **사업소득 3.3%**: 같은 사람이 반복·계속해서 일하면 세무서가 사업소득으로 보는 경우가 많다. 소득세 3% + 지방소득세 0.3%
- 세액은 10원 미만을 버린다.
- 원스텝처럼 같은 인력이 꾸준히 참여하는 구조라면 사업소득에 해당할 수 있으니 **세무사 확인을 권장**한다.

세목, 과세최저한 적용 단위, 10원 미만 처리 시점, 지방소득세 계산 순서와 예외는 실제 지급 전 세무사에게 확인한다. 설정 변경에는 적용 시작일·변경자·변경 사유를 기록한다. 지급일 규칙은 주말·공휴일, 말일, 유예 기간의 달력일/영업일 기준을 대표에게 확인한다. `N시간/일 전` 설정은 한국시간 기준 마감 시각을 명시한다. `직접 입력`은 승인 권한과 입력 범위를 제한한다.

**SET-08 참고**: 여성 수험생 안내 등 성별이 필요한 현장이 있다면 수집한다. 필요 없다면 개인정보 최소 수집 원칙에 따라 받지 않는다.

## 6. 비기능 요구사항

### 6.1 보안·개인정보
| 항목 | 요구사항 |
|---|---|
| 주민번호·계좌번호 | 서버에서 암호화(AES-256-GCM)해 저장한다. 주민번호 암호화는 개인정보보호법상 의무다. 화면에는 가려서 보여 준다. |
| 민감정보 열람 | 원문은 대표만 볼 수 있고, 볼 때마다 열람 기록을 남긴다. |
| 권한 | 데이터베이스 행 단위 보안(RLS)으로 회원은 자기 데이터만 읽고 쓴다. 관리자 기록과 고객사 정보는 회원에게 보이지 않는다. |
| 파일 | 계약서 PDF와 서명 이미지는 비공개 저장소에 두고, 짧은 시간만 유효한 링크로 내려준다. |
| 동의 | 가입 시 개인정보 수집·이용 동의(필수)를 받는다. 개인정보처리방침 페이지를 둔다. |
| 보관·파기 | 탈퇴 시 서비스 이용용 프로필을 정리한다. 계약·세무자료의 법정 보관 대상·기간과 회원 식별 정보의 분리·익명화 방법은 법률·세무 검토 후 확정하고, 기간 만료 시 파기한다. |
| 접속 | 모든 통신은 HTTPS. 로그인은 카카오·구글 인증에 맡기고 비밀번호를 저장하지 않는다. |

주민번호·계좌번호는 필요한 계약·정산 단계에서만 수집한다. 가입·일정 신청 단계에서는 요구하지 않는다. 무료 시연에는 가짜 데이터를 사용한다.

### 6.2 사용성
- 회원 화면은 휴대폰 한 손 사용 기준으로 만든다. 글씨는 크게, 단계는 짧게.
- 다양한 연령대가 쓰므로 전문 용어 대신 쉬운 말을 쓴다.
- 지원 환경: 최신 모바일 Chrome·Safari, 카카오톡 인앱 브라우저, PC Chrome·Edge

### 6.3 운영
- 개발·유지보수는 2인(개발 초보자 포함)이 맡는다. 서버를 직접 관리하지 않는 관리형 서비스를 쓴다.
- 코드는 GitHub에 두고, 변경하면 자동 배포한다.

## 9. 성공 지표 (사용성 검증)

| 지표 | 목표 |
|---|---|
| 핵심 인력 가입률 | 초대 후 2주 안에 핵심 인력의 80% 이상 가입 |
| 앱 신청 비율 | 시범 일정 신청의 90% 이상이 앱으로 들어옴 |
| 계약 서명 완료율 | 확정 후 24시간 안에 90% 이상 서명 |
| 대표 처리 시간 | 일정 1건(등록 → 확정 → 계약 완료)에 드는 시간이 기존보다 줄어듦 (시범 전에 기존 소요 시간 측정) |
| 만족도 | 시범 운영 후 대표·참여 인력 인터뷰에서 "계속 쓰겠다" 응답 |

측정 전에 시범 대상자 5~10명과 일정 2~3건을 정하고, 각 지표를 `달성 건수/대상 건수`로 기록한다. 작은 표본에서는 비율과 건수를 함께 보고 목표 미달 원인도 기록한다.

- **가입률**: 시범 가입률(초대한 시범 인력 중 2주 안에 승인·필수 프로필 입력을 마친 인원)과 전체 핵심 인력 확산률(전체 대상에게 초대한 뒤 2주 안에 완료한 인원)을 분리한다. 위 80% 목표는 전체 확산 단계에 적용한다.
- **앱 신청 비율**: 시범 일정의 전체 신청·직접 추가 중 회원이 앱에서 직접 신청한 건수의 비율로 계산한다.
- **계약 서명 완료율**: 취소·무효 요청을 제외한 유효 서명 요청 중 요청 후 24시간 안에 완료한 건수의 비율로 계산한다.
- **대표 처리 시간**: 시범 전 유사 일정의 등록부터 계약 완료까지 걸린 시간을 기록하고, 시범 일정의 같은 구간과 비교한다. 비교할 일정 수와 목표 감소율은 시범 전에 정한다.
- **만족도**: 대표와 참여 인력의 응답을 따로 기록하고, 응답자 수와 계속 사용할 의향이 있는 응답 수를 함께 남긴다. 합격 기준은 시범 전에 정한다.
- **운영 안전성**: 개인정보 오노출, 잘못된 지급액, 업무 중단 발생 건수를 별도로 기록한다. 발생하면 출시 판단 전에 원인과 재발 방지를 검토한다.
