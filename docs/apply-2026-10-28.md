# 2026-10-28 작업 적용하기 (순서대로)

> 14번은 PR 검수 뒤에 더해졌다. 10~13번을 이미 실행했다면 **14번만** 실행하면 된다.

브랜치 `claude/busy-keller-psw6a1`에 쌓인 작업을 실제 서비스에 올리는 순서다.
새 코드는 새 DB 함수를 부르므로 **DB(SQL)를 먼저, 코드(배포)를 나중에** 한다. SQL은 모두 데이터를 지우지 않고 더하기만 하므로, 먼저 실행해도 지금 서비스는 그대로 돌아간다.

| 단계 | 누가 | 할 일 | 걸리는 시간 |
|---|---|---|---|
| 1 | 개발자 | DB 백업 (권장) | 5분 |
| 2 | 개발자 | 어디까지 실행했는지 확인 | 1분 |
| 3 | 개발자 | SQL 10 → 11 → 12 → 13 → 14 실행 | 5분 |
| 4 | 개발자 | 코드를 `main`에 합치기 → 자동 배포 | 5분 |
| 5 | 개발자 | 개발자 계정 등록 | 2분 |
| 6 | 개발자 | 배포된 화면에서 확인 | 20분 |
| 7 | 대표 | 회사 정보 입력, 명단 붙여넣기 | 10분 |

---

## 1. DB 백업 (권장)
[DB 백업하기](./backup.md)를 따라 DBeaver로 한 번 받아 둔다. 이번 SQL은 데이터를 지우지 않지만, 실제 회원 정보가 있다면 해 두는 편이 안전하다.

## 2. 어디까지 실행했는지 확인
Supabase 대시보드 > **SQL Editor**에 아래를 붙여 넣고 Run.

```sql
select
  (select count(*) from information_schema.columns where table_schema = 'public' and table_name = 'job_roles' and column_name = 'default_for') > 0 as "8번",
  to_regclass('public.contracts') is not null as "9번",
  exists (select 1 from public.app_settings where key = 'pilot') as "10번",
  to_regclass('public.app_errors') is not null as "11번",
  (select count(*) from information_schema.columns where table_schema = 'public' and table_name = 'profiles' and column_name = 'withdrawn_at') > 0 as "12번",
  to_regclass('public.roster') is not null as "13번",
  (select count(*) from pg_proc where proname = 'withdraw_member' and pronargs = 3) > 0 as "14번";
```

- `true`인 번호는 이미 실행한 것이다. **다시 실행하지 않는다** (같은 표를 또 만들려다 오류가 난다).
- 8번·9번이 `false`면 README "4. 데이터베이스 만들기" 표대로 그것부터 실행한다.

## 3. SQL 실행 (`false`인 것만, 번호 순서대로)
각 파일을 GitHub에서 열어 **Raw** 버튼 → 전체 복사 → SQL Editor에 붙여 넣고 Run. 하나씩 실행한다.

| 순서 | 파일 | 하는 일 |
|---|---|---|
| 10 | `supabase/migrations/20261105000000_pilot_metrics.sql` | 시범 운영 지표 설정 한 줄 |
| 11 | `supabase/migrations/20261106000000_dev_console.sql` | 개발자 등록 표, 오류 기록, 시범 지표를 개발자만 |
| 12 | `supabase/migrations/20261107000000_privacy_withdrawal.sql` | 회원 탈퇴, 다시 가입, 처리방침용 회사 정보 |
| 13 | `supabase/migrations/20261108000000_roster.sql` | 기존 인력 명단, 명단 전용 초대 링크 |
| 14 | `supabase/migrations/20261109000000_review_fixes_2.sql` | 리뷰 반영 (탈퇴 확인 처리, 명단 이름 필수, 다시 가입 초기화, 오류 기록 한도) |

- "Potential issue detected" 창이 뜨면 **Run query**를 누른다. 중간에 오류가 나면 그 파일의 변경은 모두 취소되니, 오류 문구를 개발자 화면이나 대화창에 붙여 알려 준다.
- 다 하고 2번의 확인 SQL을 다시 돌려 모두 `true`인지 본다.

## 4. 코드를 `main`에 합치기 → 자동 배포
1. GitHub에서 `claude/busy-keller-psw6a1` → `main` PR을 만들고 합친다 (Merge).
2. Netlify가 자동으로 다시 배포한다. Netlify > Deploys에서 **Published**가 뜰 때까지 기다린다 (보통 2~3분).
3. 환경변수는 새로 넣을 것이 없다.

## 5. 개발자 계정 등록 (오류 기록·시범 지표 화면)
1. 배포된 주소의 `/login?next=/dev`에서 본인 Google 계정으로 로그인한다. "찾을 수 없음"이 나오면 정상이다.
2. SQL Editor에서 실행한다. 결과에 한 줄이 나오면 된다.
   ```sql
   insert into public.developers (user_id, note)
   select id, '<개발자 이름>' from auth.users where email = '<개발자 Gmail>'
   returning user_id;
   ```
3. 새로고침하면 `/dev`(오류 기록)와 `/dev/pilot`(시범 운영 지표)이 열린다.

## 6. 배포된 화면에서 확인
대표 계정과 연습용 회원 계정(다른 Google 계정, 시크릿 창)을 같이 쓴다. 이상하면 `/dev` 오류 기록부터 본다.

| 확인 | 어떻게 | 기대 결과 |
|---|---|---|
| 회원 탭 | 대표: 왼쪽 메뉴 **회원** | 탭 4개(회원 목록·가입 승인·초대 링크·명단으로 초대)가 보이고 눌러 오갈 수 있다 |
| 명단 넣기 | 명단으로 초대 탭에 엑셀 2~3줄(본인 번호 포함) 붙여넣기 | 미리보기에 읽은 인원이 뜨고, 넣으면 목록에 "가입 전"으로 보인다 |
| 단체 링크 | 명단의 "단체 링크 만들기" → 시크릿 창에서 링크 열기 | 명단에 **없는** 번호로 신청하면 막히고, **있는** 번호로는 신청된다 |
| 가입 승인 대조 | 대표: 가입 승인 탭 | "명단에 있어요 · …", 등급이 명단대로 골라져 있다 |
| 개인 링크 | 휴대폰에서 명단 탭 → 개인 링크 만들기 → 문자 보내기 | 문자 앱이 번호·문구가 채워져 열린다 (아이폰·안드로이드 각각) |
| 일정 복사 | 대표: 지난 일정 상세 → "이 일정 복사해서 새로 만들기" → 1일차 날짜만 고르고 저장 | 나머지 날짜가 원래 간격대로 채워지고, 임시저장 일정이 새로 생긴다 |
| 처리방침 | 로그아웃 상태로 `/privacy` | 로그인 없이 열리고, 보호책임자 칸에 회사 정보가 나온다 |
| 탈퇴 | 연습 회원: 내 정보 맨 아래 **회원 탈퇴** | 탈퇴 후 로그인 화면에 "탈퇴했어요", 대표에게 알림. 같은 계정으로 초대 링크를 열면 다시 신청할 수 있다 |
| 오류 기록 | 끈 초대 링크를 시크릿 창에서 열기 → 개발자: `/dev` | "안내한 오류 · INVITE_INVALID" 한 건이 생긴다 |
| 대표에게 안 보임 | 대표 계정으로 `/dev` 열기 | "찾을 수 없음" |

연습으로 만든 회원·명단·일정은 실제 운영 전에 `supabase/scripts/reset_test_data.sql`로 지운다 (README "연습 데이터 지우기").

## 7. 대표님이 하실 것
1. **설정 > 회사 정보**에 대표자 이름·연락처 입력 → 처리방침의 개인정보 보호책임자 칸에 나온다.
2. **회원 > 명단으로 초대**에 핵심 인력 명단 붙여넣기 → 단체 링크를 만들어 핵심 인력 톡방에 올리기.
3. 답해 주실 것
   - 고객사에 투입 인력 명단(이름·연락처)을 주는지. 주면 가입 동의에 "제3자 제공"을 따로 넣어야 한다.
   - 기존 방식으로 일정 1건(등록 → 계약 완료)에 걸리던 시간 (시범 지표 비교용, 결정 #25).
4. 바뀐 메뉴(회원 탭)는 사용 안내 PDF와 다르다. 안내서를 고치기 전에는 "가입 승인·초대 링크는 회원 메뉴 안 탭으로 옮겼어요"라고 전한다.
