# 원스텝 (onestep)

면접·필기시험·행사 진행요원 파견을 위한 인력 관리 앱.
초대받고 승인된 프리랜서 인력이 일정을 신청하고, 대표가 선발·계약·정산까지 한 곳에서 처리한다.

## 처음 설정하기

처음 한 번만 하면 된다. 메뉴 이름은 각 서비스가 바꿀 수 있으니, 비슷한 이름을 찾으면 된다.

### 1. 준비물
- [Node.js](https://nodejs.org) 22 버전 (20.9 이상이면 동작)
- Git
- Supabase, 카카오 개발자, Google Cloud 계정 (개발자 본인 계정으로 만들어도 된다. 아래 "계정과 권한" 참고)

### 계정과 권한
개발과 시연(가짜 데이터)은 **개발자 본인 계정**으로 시작한다. 다만 회사 서비스가 한 사람 계정에만 묶이지 않도록, 실제 개인정보를 넣기 전에 대표를 관리자로 추가한다.

| 서비스 | 지금 (개발자) | 대표가 할 일 |
|---|---|---|
| Supabase | 조직(Organization)과 프로젝트를 만든다 | 실제 운영 전: 조직에 **Owner**로 초대받는다. 유료 전환 시 결제 수단 등록 |
| Google Cloud | 프로젝트와 OAuth 클라이언트를 만든다 | 실제 운영 전: IAM에서 **소유자**로 추가된다 |
| 카카오 개발자 | 앱을 만들고 설정한다 | **비즈 앱 전환 때 꼭 필요**: 대표 카카오 계정으로 개발자 등록 → 개발자가 멤버로 추가하고 Owner로 바꿈 → 대표가 사업자 정보 등록 (6단계) |

### 2. 코드 받고 설치
```bash
git clone https://github.com/dydtlsrl/onestep.git
cd onestep
git switch claude/workforce-management-app-35e05f
npm ci
```
- `npm ci`는 `package-lock.json`에 적힌 버전 그대로 라이브러리를 설치한다. 라이브러리는 이 폴더의 `node_modules`에만 들어가므로 Python처럼 가상환경을 따로 만들 필요가 없다.
- 새 라이브러리를 추가할 때만 `npm install <이름>`을 쓴다.
- 여러 프로젝트에서 Node 버전이 다르면 [fnm](https://github.com/Schniz/fnm)을 쓴다. 이 폴더의 `.nvmrc`(Node 22)를 읽어 버전을 맞춰 준다.

### 3. Supabase 프로젝트 만들기
1. [supabase.com](https://supabase.com)에서 New project를 누른다. 지역(Region)은 **Northeast Asia (Seoul)** 를 고른다.
2. 두 값을 확인한다.
   - **Project URL**: `https://<Project ID>.supabase.co`. Project ID는 Settings > General에 있다. 화면 위쪽 **Connect** 버튼을 눌러도 주소가 나온다.
   - **Publishable key**: Settings > **API Keys**에 있는 `sb_publishable_`로 시작하는 키
3. 이 폴더에서 `.env.example`을 복사해 `.env.local`을 만들고 두 값을 채운다.
   ```bash
   cp .env.example .env.local
   ```
   `service_role` 키나 secret 키는 넣지 않는다. 브라우저에 노출되면 안 되는 키다.
4. **개인정보 암호화 키**를 만들어 `.env.local`의 `PII_ENCRYPTION_KEY`에 넣는다. 아래 "암호화 키 만들기"를 따른다.

### 암호화 키 만들기
회원의 주민등록번호·계좌번호는 앱 서버에서 이 키로 암호화한 뒤에 DB에 저장한다. 키는 DB에도 GitHub에도 없고, `.env.local`(내 컴퓨터)과 배포한 서버의 비밀 환경변수에만 둔다.
1. 터미널에서 아래 명령을 실행하면 키(영문·숫자 44자)가 한 줄 나온다.
   ```bash
   node -e "console.log(require('crypto').randomBytes(32).toString('base64'))"
   ```
2. `.env.local`에 `PII_ENCRYPTION_KEY=<나온 값>`으로 넣고 서버를 다시 켠다. 채팅·메신저·GitHub에 붙여 넣지 않는다.
3. **같은 키를 비밀번호 관리자 등 안전한 곳에 따로 보관한다.** 키를 잃어버리면 저장된 주민번호·계좌번호를 다시 읽을 수 없다 (회원이 다시 입력해야 한다). 키를 바꾸면 기존 값도 읽을 수 없게 된다.
4. 배포할 때는 호스팅 서비스(예: Vercel)의 환경변수 화면에 같은 값을 넣는다. 대표 화면 > 설정 맨 위에 키가 설정되었는지 나온다.

### 4. 데이터베이스 만들기
Supabase 대시보드 > **SQL Editor**에서 `supabase/migrations` 폴더의 파일을 **이름 순서대로 하나씩** 붙여 넣고 **Run**을 누른다.
테이블, 권한 규칙(RLS), 가입 신청·승인·회원 관리 함수가 만들어진다.

| 순서 | 파일 | 내용 |
|---|---|---|
| 1 | `20261027000000_phase1_auth_invites.sql` | 회원, 초대 링크, 가입 신청·승인 |
| 2 | `20261028000000_phase1b_members_rates.sql` | 관리자 기록, 단가표, 등급 변경·활동 제한 |
| 3 | `20261029000000_pay_rules.sql` | 시급·일급, 최소 보장 시간, 초과 시간 보수, 공통 계산 규칙 |
| 4 | `20261030000000_events.sql` | 일정, 모집 역할, 추가 지급, 신청·선발·출석, 알림, 톡방 링크 |
| 5 | `20261031000000_event_days.sql` | 여러 날짜 일정 (세팅일·진행일), 날짜별 신청·선발·출석. 이미 만든 일정은 1일차짜리로 바뀐다 |
| 6 | `20261101000000_review_fixes.sql` | 알림 길이 제한(긴 제목·긴 취소 사유), 활동 제한된 회원의 톡방 링크 차단 |
| 7 | `20261102000000_day_signup.sql` | 날짜만 골라 신청, 날짜별 모집 인원·단가, 신청자마다 역할·단가, 회원 기본 시급, 기본 시급 설정 |
| 8 | `20261103000000_rate_presets.sql` | 단가표의 ★세팅일 기본·진행일 기본 표시. 처음 기본 단가 2줄(시급 11,000원) 추가 |

| 10 | `20261105000000_pilot_metrics.sql` | 시범 운영 지표 설정(시범 일정·초대 링크, 초대 인원, 기존 처리 시간, 인터뷰·사고 건수). 데이터를 지우지 않음 |
| 11 | `20261106000000_dev_console.sql` | 개발자 화면: 개발자 등록 표, 오류 기록, 시범 운영 지표를 개발자만 보게. 데이터를 지우지 않음 |
| 12 | `20261107000000_privacy_withdrawal.sql` | 회원 탈퇴(대표 대신 처리 포함), 정산 정보 보관 기한·자동 삭제, 탈퇴한 사람 다시 가입, 처리방침용 회사 정보. 데이터를 지우지 않음 |
| 13 | `20261108000000_roster.sql` | 기존 인력 명단, 초대 링크의 "명단 번호만 가입"·개인 링크. 데이터를 지우지 않음 |

시험용 샘플 일정이 필요하면 `supabase/samples/sample_events.sql`을 실행한다 (제목이 [샘플]로 시작, 맨 아래 한 줄로 지움).

이미 적용한 파일은 다시 실행하지 않는다 (같은 테이블을 또 만들려고 해서 오류가 난다). 새 파일이 생기면 그 파일만 실행한다.
Run을 누를 때 "Potential issue detected (destructive operations)" 창이 뜰 수 있다. 파일 맨 위 설명에 무엇을 지우는지 적어 두었으니 확인하고 **Run query**를 누른다. 중간에 오류가 나면 그 파일의 변경은 모두 취소된다.

### 5. 로그인 주소 등록
Supabase > Authentication > **URL Configuration**
- Site URL: `http://localhost:3000`
- Redirect URLs에 추가: `http://localhost:3000/**`
- 배포한 뒤에는 실제 주소(예: `https://onestep.co.kr/**`)도 추가한다.

### 6. 카카오 로그인 설정
1. [developers.kakao.com](https://developers.kakao.com)에서 애플리케이션을 추가한다. (개발자 계정으로 만들어도 된다)
2. 앱 키의 **REST API 키**를 복사해 둔다. (Supabase의 Client ID로 쓴다)
3. 카카오 로그인을 **활성화**하고, Redirect URI에 아래 주소를 등록한다.
   `https://<프로젝트ID>.supabase.co/auth/v1/callback`
   (프로젝트ID는 3단계의 Project URL에 들어 있는 영문자)
4. 보안 메뉴에서 **Client Secret**을 만들고 사용함으로 바꾼 뒤 복사해 둔다.
5. **비즈 앱으로 전환**한다. 앱 소유자(Owner)만 할 수 있으므로 대표와 함께 한다.
   1. 대표가 본인 카카오 계정으로 카카오 개발자 사이트에 가입한다.
   2. 개발자가 앱 > **멤버 > 멤버 추가**로 대표 계정을 추가하고, 권한을 **Owner**로 바꾼다. (개발자는 멤버로 남아 계속 설정할 수 있다)
   3. 대표가 앱 > 일반 > **비즈니스 정보 > 사업자 정보 등록**에서 원스텝 사업자등록번호를 넣는다.
6. 동의항목에서 닉네임, 프로필 사진, **카카오계정(이메일)** 을 설정한다. 이메일은 선택 동의로 해도 된다.
   Supabase의 카카오 로그인은 로그인할 때마다 이메일 항목을 함께 요청하므로, 이메일 동의항목이 설정되어 있지 않으면 `KOE205` 오류가 난다.
7. Supabase > Authentication > **Sign In / Providers > Kakao**를 켜고 REST API 키와 Client Secret을 넣는다.
   **Allow users without an email**도 켠다. 이메일 제공에 동의하지 않은 사람도 로그인할 수 있게 하기 위해서다.
8. 환경변수 `NEXT_PUBLIC_KAKAO_LOGIN=on`을 넣는다 (로컬은 `.env.local`, 배포는 호스팅 환경변수 후 다시 배포). 넣기 전에는 로그인 화면에 카카오 버튼이 보이지 않는다.

### 7. Google 로그인 설정
1. [console.cloud.google.com](https://console.cloud.google.com)에서 프로젝트를 만들고 **OAuth 동의 화면**을 설정한다. (앱 이름: 원스텝)
2. 사용자 인증 정보 > **OAuth 클라이언트 ID** > 웹 애플리케이션을 만든다.
3. 승인된 리디렉션 URI에 `https://<프로젝트ID>.supabase.co/auth/v1/callback`을 넣는다.
4. 만들어진 클라이언트 ID와 보안 비밀번호를 Supabase > Sign In / Providers > **Google**에 넣고 켠다.

### 8. 실행
```bash
npm run dev
```
브라우저에서 http://localhost:3000 을 연다.

### 9. 첫 대표 계정 만들기
대표 계정은 초대 링크 없이 한 번만 직접 만든다.
1. 대표가 사이트 로그인 화면에서 본인 Google 계정으로 로그인한다. ("아직 가입 신청 전이에요" 화면이 나오면 된다)
   Google 로그인이 "테스트 중"이면 그 Gmail을 Google Cloud > Google 인증 플랫폼 > 대상 > **테스트 사용자**에 먼저 넣는다.
2. Supabase SQL Editor에서 아래를 실행한다. 꺾쇠 안의 값을 바꾼다. 결과에 한 줄(id, name)이 나오면 된다. 아무것도 안 나오면 그 이메일로 아직 로그인한 적이 없는 것이다.
   ```sql
   insert into public.profiles (id, name, phone, role, status, tier, privacy_agreed_at, approved_at)
   select id, '<대표 이름>', '<휴대폰 숫자만, 예: 01012345678>', 'admin', 'active', 'core', now(), now()
   from auth.users where email = '<대표 Gmail>'
   returning id, name;
   ```
   이메일을 모르면 "아직 가입 신청 전이에요" 화면의 **내 계정 ID 보기**로 ID를 받아 `where id = '<계정 ID>'`로 바꿔 실행해도 된다.
3. 대표가 새로고침하면 대표 화면(`/admin`)이 열린다.

### 10. 개발자 화면 열기 (`/dev`)
오류 기록과 시범 운영 지표는 개발자만 본다. 개발자는 회원으로 가입하지 않아도 된다.
1. 개발자가 `/login?next=/dev`에서 본인 Google 계정으로 로그인한다. (처음엔 "찾을 수 없음" 화면이 나오면 된다)
2. Supabase SQL Editor에서 아래를 실행한다. 결과에 한 줄이 나오면 된다.
   ```sql
   insert into public.developers (user_id, note)
   select id, '<개발자 이름>' from auth.users where email = '<개발자 Gmail>'
   returning user_id;
   ```
3. 새로고침하면 개발자 화면이 열린다. 빼려면 `delete from public.developers where user_id = '<ID>';`

어떤 오류가 기록되나
| 종류 | 언제 |
|---|---|
| 버그 의심 · 화면 열기 | 화면을 만들다 서버에서 난 오류 (`src/instrumentation.ts`), 대표 목록 화면의 "불러오지 못했어요" |
| 버그 의심 · 버튼·저장 | 저장 버튼을 눌렀는데 DB가 모르는 이유로 거절한 경우 |
| 버그 의심 · 브라우저 | 휴대폰·PC 브라우저에서 난 오류 (`src/components/error-listener.tsx`, `app/error.tsx`) |
| 버그 의심 · 로그인 | 카카오·Google 로그인에서 돌아올 때 실패 |
| 안내한 오류 | 앱이 안내 문구를 보여 준 경우 (신청 마감, 만료된 초대 링크, 정산 정보 미등록 등). 많으면 사람들이 막히는 곳 |

오류는 180일이 지나면 지워지고, 하루 5,000건·1분 120건(한 사람 30건)을 넘으면 더 남기지 않는다. 화면에 "오류 번호"가 보이면 개발자 화면에서 그 번호로 찾는다.

### 11. 직접 해 보기
1. 대표 화면 > 회원 > **초대 링크** 탭에서 링크를 만들고 복사한다.
2. 다른 브라우저(또는 시크릿 창)에서 그 링크를 열고, 다른 계정으로 로그인해 가입 신청서를 낸다.
3. 대표 화면 > 회원 > **가입 승인** 탭에서 등급을 골라 승인한다.
4. 신청한 쪽 화면을 새로고침하면 환영 화면이 나온다.

계약·정산까지 한 바퀴 돌려 보기
1. 대표: 설정에서 회사 정보와 세금 처리 방식을 정한다 (세무사 확인 전이면 "아직 정하지 않음"으로 두고 연습해도 된다).
2. 대표: 일정을 만들고 공개 → 회원이 신청 → 대표가 확정하고 "선발 결과 알림 보내기".
3. 대표: 일정 상세 > **계약** 탭에서 "계약서 보내기". 회원에게 알림이 간다.
4. 회원: 알림을 눌러 계약서를 열고, 정산 정보(주민번호·계좌)를 등록한 뒤 서명한다. "인쇄 · PDF로 저장"으로 PDF를 받을 수 있다.
5. 대표: 출석 확인 탭에서 출석을 기록 → **정산** 탭에서 "출석 기록으로 정산 만들기". 필요하면 사람별로 항목을 고친다.
6. 대표: 정산 메뉴에서 지급일을 고르고 "이체 파일 받기" → 은행 대량이체 → 고른 사람을 "지급 완료로 바꾸기". 회원에게 알림이 가고 회원 정산 내역에 나온다.

시범 사용 전과 실제 운영 직전에 `supabase/scripts/reset_test_data.sql`을 SQL Editor에서 실행한다. 관리자 계정·설정·★기본 단가·기본 계약서 양식만 남기고 일정·회원·정산 등을 지운다. 되돌릴 수 없다.

## 검사 명령
코드를 고친 뒤 올리기 전에 실행한다.

| 명령 | 하는 일 |
|---|---|
| `npm run lint` | 코드 실수 검사 |
| `npm run typecheck` | 타입 검사 |
| `npm test` | 단위 테스트 (휴대폰 번호, 초대 코드, 입력값 검사 등) |
| `npm run db:test` | 임시 PostgreSQL에 마이그레이션을 적용하고 권한 규칙(RLS)을 검사. PostgreSQL 15 이상 필요 |
| `npm run build` | 배포용 빌드 |

`NEXT_PUBLIC_`으로 시작하는 환경변수는 빌드할 때 코드에 들어간다. 값을 바꾸면 다시 빌드해야 한다.

## 폴더 구조
```
src/
  app/                 화면 (폴더 이름이 주소가 된다)
    admin/             대표 화면 (events/ = 일정, (people)/ = 회원 화면의 탭: 회원 목록·가입 승인·초대 링크)
    dev/               개발자 화면 (오류 기록, 시범 운영 지표)
    events/[id]/       회원이 보는 일정 상세·신청
    contracts/         회원 계약서 보기·서명
    payments/          회원 정산 내역
    me/                내 정보 (정산 정보 등록)
    notifications/     알림
    join/[code]/       초대 링크 첫 화면
    signup/[code]/     가입 신청서
    auth/              로그인 콜백, 로그아웃
  components/          여러 화면에서 쓰는 부품 (버튼, 카드 등)
  lib/                 화면이 아닌 코드 (Supabase 연결, 입력값 검사, 날짜·번호 형식)
  proxy.ts             모든 요청 전에 로그인 세션을 갱신 (Next.js 16의 proxy)
  instrumentation.ts   서버에서 난 오류를 오류 기록(app_errors)에 남김
supabase/
  migrations/          데이터베이스 변경 SQL. 순서대로 적용한다
  tests/               권한 규칙 테스트
docs/                  기획 문서
```

## 자주 생기는 문제
| 증상 | 확인할 것 |
|---|---|
| "Supabase 환경변수가 없습니다" | `.env.local`이 있는지, 값을 채웠는지, 서버를 다시 켰는지 |
| 카카오 로그인 중 `KOE205` | 6단계 5·6번: 비즈 앱 전환과 이메일 동의항목 |
| 로그인 후 `redirect_uri_mismatch` 또는 다른 주소로 감 | 5단계 Redirect URLs, 6·7단계의 Supabase 콜백 주소 |
| 카카오톡에서 Google 로그인이 안 됨 | 정상이다. 화면의 "기본 브라우저로 열기"를 누른다 |
| 대표 화면이 안 열림 | 9단계 SQL에서 role이 `admin`, status가 `active`인지 |
| 일정 화면에 "일정을 불러오지 못했어요" | 4단계 표의 4~9번 파일을 순서대로 실행했는지 |
| 정산 정보 저장 때 "암호화 키가 설정되지 않았어요" | `.env.local`에 `PII_ENCRYPTION_KEY`를 넣고 서버를 다시 켰는지 (3단계 "암호화 키 만들기") |
| 원문 보기·이체 파일에 "복호화 실패" | 저장할 때와 다른 키를 쓰고 있다. 보관해 둔 원래 키로 바꾼다 |
| 정산이 "확정 전"에서 안 바뀜 | 설정에서 세금 처리 방식을 고른 뒤 일정 정산 탭에서 "다시 계산" |
| 이체 파일 받기가 눌리지 않음 | 그 지급일에 "지급 예정"인 정산이 있어야 한다 (확정 전·보류는 빠진다) |
| 회원이 공개한 일정을 못 봄 | 회원이 활동(`active`) 상태인지. 핵심 공개 중이면 핵심 회원만 보인다 |
| 확정자가 톡방 링크를 못 봄 | 대표가 일정 상세의 "선발 결과 알림 보내기"를 눌렀는지. 알림을 보낸 뒤에 보인다 |
